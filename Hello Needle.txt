# Hello Needle project record

**Alfredo Llaquet-Alsina** created Hello Needle. **Programmed by ChatGPT.** Leopold Luley and the Clapgrep contributors wrote the application from which this project derives. Keep both credits specific to their work. [Attribution](NOTICE.md)

## How to maintain this record

This file is the living manual for decisions, development notes, controls, source responsibilities, build procedures, and verification. Update the affected sections **in the same change as the program**. Replace superseded instructions and date substantive decisions. Report tested systems and evidence precisely. The README describes the application for someone installing or using it. The license texts, fixtures, and automated tests are the authoritative artifacts for their respective subjects.

This practice comes from Crumb Writer’s rule to keep its detailed manual synchronized with the program. Hello Needle’s root `AGENTS.md` directs contributors to read, follow, and maintain `Hello Needle.txt`. The full instructions and project history belong here. A new contributor should be able to trace a result from the keyboard to the matching text, find the responsible module, and reproduce the test. ## Using the desktop

Choose a local folder, enter a phrase, and press Enter. Selecting a matching occurrence in the results tree opens its preview. The folder picker also responds to the platform’s Open shortcut. The Find shortcut returns focus to the search field. Escape cancels active work. The preview’s normal Copy action copies the selected text. Opening an original file in its usual application is explicit. Searches and previews leave original files intact.

On the search form, **Options**, **Search in**, and the **Document/Source** selector sit together on one row. Above a selected preview, show its location and filename in that order, joined by ` - `. Reserve a second title line when the filename wraps, including in compact windows. Directly below it, display **Directory** with the absolute native parent directory on a separate, selectable, wrapping line. A directory that exceeds its available height can be scrolled and copied. Keep **Open original** below the directory, aligned to the same left edge. Use the reader’s own location, such as a paragraph, PDF page, source line, or sheet and cell.

Four icon-only buttons under **Results** follow this order: next document (Ctrl+Down), next match (F3 or Alt+Down), previous match (Shift+F3 or Alt+Up), previous document (Ctrl+Up). The controls become available with the first hit, including during a search. A document jump selects its first occurrence, and match navigation follows the tree across document boundaries. Wrap around the currently available results. Expand the destination group, scroll the occurrence into view and update the preview. The **View** selector beside **Results** offers **File names** (the default), **File paths** and **Folder tree**. File names sort by basename, with the relative path breaking ties. File paths displays paths relative to the search folder. Folder tree groups the same files under expandable directories, with folders first at each level. When the results pane is narrow, the selector moves below the heading so each translated option stays readable. The index uses native file identities, so two identically named files remain distinct. Switching views preserves the selected occurrence and preview, even while the search is running. Navigation opens the required ancestors and crosses page boundaries. Single and double Lucide chevrons distinguish occurrence and document navigation. Both interface languages supply accessible names and shortcut hints.

The preview centers a selected text line vertically, including the first and last lines. Leave the user free to scroll after the initial selection. In a zoomed PDF with word coordinates, center the highlighted words within the scrollable range. A 24-logical-pixel gap separates the splitter handle from the entire preview column. On short landscape windows, keep the results and preview side by side when both fit. On a narrow or portrait window that uses the stacked arrangement, the gap moves above the preview.

The left side of the status bar shows scan progress and matches. English displays **1 file scanned** or **%1 files scanned**. Spanish displays **1 archivo examinado** or **%1 archivos examinados**. Count every regular file encountered after the hidden, ignore and path filters, once per search. This includes files that fail to open, files without hits, unsupported binaries, PDFs without searchable text, and files whose provisional matches are subsequently withdrawn. On the right, show the error count immediately beside **Details…** (**Detalles…**) when a file or operation fails. An unsupported binary or an image-only PDF produces zero content matches and adds zero errors.

The centered link displays ordinary text at rest. Its English label is `Read Alfredo Llaquet-Alsina's Crumbs at TheCrumbs.org`. Hovering anywhere on the text underlines the entire label and shows `Open TheCrumbs.org in your browser`. Activating any part opens `https://www.thecrumbs.org` in the default browser. If the counts, the link and the button cannot fit on one row, center the link on its own row below the counts. Determine that layout from the width the status bar actually receives when the window opens. On a 1024 × 768 desktop at 150% scaling, the available work area on Windows can be as small as 683 × 480 logical pixels.

Ship the button icons with the application on all four platforms. Use Lucide’s open folder for **Browse…**, magnifying glass for **Search**, stop square inside a circle for **Cancel**, horizontal sliders for **Options**, bulleted list for **Details…**, and arrow leaving a square for **Open original**. Show labels on these six controls. The four result navigation buttons use icons and tooltips. Derive each icon’s color from the button palette. Keep the applicable artwork notices with the other license texts.

The default is a case-insensitive literal search. Options expose regular expressions, case sensitivity, hidden and ignored entries, matching filenames, and a path glob and **Exclude subdirectories**. By default the walk is recursive. Enabling this option searches only files directly inside the chosen folder, including for filename searches. The option and the results view are remembered independently. A filename match carries the `filename` kind and is distinct from a passage. Errors from individual files are counted while readable files continue. The worker scans until traversal finishes or the search is canceled. Each search has a temporary SQLite index of file identities, all occurrences and every error. The GUI pages files, occurrences and error details independently. The index is closed when the search is replaced or the window closes. If the temporary index can no longer be written, the search stops and the desktop explains the storage failure. Cancel retains the results already received. New searches and canceled previews have distinct process identities, so a stale response cannot revive an old selection.

The window groups matches by file, gives the preview more space, and adapts the split layout to the window. Qt supplies native control, menu and dialog behavior. Enabled prompts, typed field text, preview guidance and application-painted menu lettering are tested against a 4.5:1 glyph contrast threshold. Disabled actions and operating-system-owned controls are recorded separately. Use descriptive visible control labels, the platform font and palette, and local project artwork for the application icon. Check typed text, placeholder text, focus, selections and disabled controls against the surface they are drawn on. Settings retain the last folder, options, language choice and window layout. The clean-start test uses a fresh profile for each configuration.

The English–Spanish catalog in `desktop/qt/language.cpp` covers application controls, statuses, result locations and worker error categories. Keep both sides of every new string together, preserving placeholders and plural distinctions. The older GTK tree uses English source strings and the single `locale/es.po` translation. Preserve the original Spanish translator credits there. The operating system supplies the native file picker's own controls.

### Performance preferences

**File → Settings…** (**Archivo → Preferencias…**) opens a modal dialog. Under **Performance**, Automatic displays half the logical processors available to the worker, rounded down with a minimum of one. Selecting a number sets a manual maximum; one requests serial file processing. The **Advanced** PDF conversion setting defaults to the smaller of two and the search worker limit. It counts conversions within the file pool. Saved values use the existing per-user QSettings store under `performance/searchWorkers` and `performance/pdfConversions`. Zero means Automatic. OK saves the choices for the next search. Cancel leaves the saved values intact. The dialog queries the installed worker's `--parallelism` command asynchronously so its Automatic display reflects the same CPU allowance used for a search.

## Search, preview, and supported formats

| Reader | Searchable representation | Location and preview |
| --- | --- | --- |
| Text | Search text lists, JSON, logs and other readable files as numbered lines. Accept UTF-8 with or without a BOM, BOM-marked UTF-16 LE/BE, and readable unmarked Windows-1252. | Preserve whitespace and measure selection offsets in UTF-16 for Qt. Long lines open at the selected occurrence with bounded context. |
| HTML / Markdown | Document mode reads visible text across inline formatting. Source mode streams saved markup, links, tags and code. Both HTML modes accept isolated terminal control characters in valid decoded text and honor supported HTML charset declarations. | Document blocks can show headings, emphasis, lists and code using a local rich fragment. Source preserves the characters on the saved line and clips exceptionally long lines around the hit. |
| PDF | Poppler streams the searchable text of each page. An image-only page retains its page number. A crash during layout extraction triggers one plain-text retry. | A hit identifies the page and line. Select it to retrieve word boxes for that line and highlight the exact occurrence on the page. A recovered hit opens with its text selected. **Show page** (**Ver página**) displays the original page without a word highlight when coordinates are unavailable. |
| DOCX / ODT / FODT | Decode the document body in reading order, joining text divided by Word runs or ODF styled spans. Stream the DOCX main story a paragraph at a time, including headings and table cells. Flat ODF is read directly. | Show the selected occurrence, its paragraph or table location, and nearby text. DOCX preview reconstructs local formatting for the selected neighborhood. Page layout depends on the originating application and fonts. |
| XLSX / ODS | Decode stored text and values. XLSX resolves workbook relationships and shared strings. ODS understands repeated row and cell coordinates. | Named sheet and A1-style cell address. Show nearby entries for context. Formula evaluation belongs to the spreadsheet application. |
| PPTX / ODP | Read presentation order and text blocks on slides. | Slide number and matching text. Text is presented in context without executing presentations or embedded objects. |
| RTF | Read paragraphs, character runs, escapes and supported character encodings. | Searchable paragraph text. Formatting commands and skipped control groups are excluded from the text. |
| Legacy DOC | Follow Word 97–2003’s active piece table. Resolve inherited paragraph and character styles, then apply character-run and piece formatting, including visibility operands `0x80` (use the style value) and `0x81` (invert it). Exclude hidden and deleted text, field instructions and non-body stories. The external `antiword` and UTF-8 map handle earlier supported variants. | Text passage with nearby context. Unsupported variants, missing streams and encryption produce diagnostics. |

A Document search for `The Latest Batch` matches `The **Latest** Batch` and `The <strong>Latest</strong> Batch`. A Source search for `<strong>` finds the markup itself. The same extractor constructs the searched and previewed text. Keep matching within individual document blocks. HTML and Markdown previews admit safe local formatting. Links, images, embedded objects and scripts must not cause network access or automatic opening of files. File names and search text can use Unicode regardless of interface language.

In HTML Document mode, `bridge/src/documents/html.rs` decodes the file incrementally. The html5gum tokenizer filters embedded resource attributes before they accumulate in memory. Inline SVG drawings and image data in styles can also be skipped as they arrive. The html5ever tree builder and the existing formatted-text reader provide the searchable blocks, including alternative text and captions. The 1 GiB per-document budget makes conservative reservations for tokenizer storage, the HTML tree, searchable text, and formatted preview content. A file that reaches the budget produces a document error, and the search proceeds to the next file. Preview uses the same reader. For an exceptionally large preview, the worker sends the portion around the selected occurrence so the GUI can show the matching passage.

Text and HTML/Markdown Source searches read up to 256 KiB of disk input at a time. Total bytes and total lines impose no search limit. Literal matching retains overlap between buffers so a hit can cross a read boundary inside a single line. The regex reader also streams expressions with a provable, practical finite width, including `[n]eedle`, while preserving nonoverlapping matches across reads. Expressions that need the whole line use a 256 MiB working budget. Recognized ANSI color and control sequences in text logs and Markdown Document mode are removed from their readable representation. Markdown Source preserves the saved control sequences. Search, highlighting and copying use the same positions in that representation. Decoding preserves CRLF boundaries and multibyte characters split between reads. When unmarked text could be UTF-8 or Windows-1252, the reader can inspect later bytes before choosing the encoding. Previews use a saved byte position when the encoding supports it and decode nearby lines around the occurrence.

HTML and Markdown in both modes honor a supported encoding marker, or an HTML encoding declaration. For an unmarked document, try strict UTF-8 and fall back to readable Windows-1252. Search and preview apply the same decoding. In an otherwise readable `.txt` file, an isolated Word-export U+001E between word characters reads as an ordinary hyphen, including across read boundaries. Keep native byte bookmarks and UTF-16 selection offsets consistent. Inside an OpenDocument package or a flat OpenDocument file, decode XML according to its own encoding signature or supported declaration. Undeclared XML follows the Unicode rules for XML.

Known video, audio, archive, executable and other unsupported binary extensions bypass content extraction. Unfamiliar and extensionless files go through the text reader. Binary data found there is skipped quietly. A file identified as a supported document still reports a genuine read, decode or format failure. **Search file names** can return a name match for a skipped file.

DOCX search streams the main XML part from the ZIP file. The number of body nodes, document paragraphs and total body bytes do not set a cutoff. A 32 MiB working limit applies to individual XML tokens, retained ancestor data and paragraph text. Nesting is limited to 512 levels. Preview keeps up to twelve surrounding paragraphs on each side within an 8 MiB context budget. Table coordinates account for skipped leading grid columns and spanned cells. ZIP directory metadata and ancillary parts such as relationship and style tables retain separate working budgets.

PDF search keeps one page of text at a time, with a 128 MiB working allowance per page. Document-wide page count, word count and accumulated geometry do not set a cutoff. Geometry is requested for the selected preview line. The Poppler subprocess may continue as long as it makes progress. A 45-second idle watchdog detects a stalled converter. After a layout crash, the plain-text retry resumes emitting matches after the last complete layout page. If both attempts fail, the diagnostic preserves their exit statuses or signals and available error text. Password-protected and unreadable PDFs still report errors. PDF search uses an existing text layer and performs no OCR.

Markdown Document mode reads independent paragraph runs in batches. Constructs that can change the interpretation of distant text, such as reference links or raw HTML, use a full CommonMark parse with a working-memory budget. Preview and copying use the same resolved blocks as search.

The Office readers visit paragraphs, cells or slides as they are decoded. They can process more than 64 MiB of input, 32 MiB of extracted text or 100,000 blocks in total. XLSX shared strings can spill to temporary files and retain lookup by index. XLSX follows the Excel grid. OpenDocument spreadsheets use their own sparse coordinates. For repeated cell values the matcher can skip a whole nonmatching run, and preview and copy can seek by logical block number. In Writer tables, row and cell repetitions contribute their logical locations, and heading and style resolution support deep acyclic chains. RTF honors large Unicode fallback counts. The Word 97–2003 reader follows the active piece table in bounded reads. Earlier Word variants handled by antiword keep running while the converter makes progress.

Preview windows keep long matches accessible by part. **Copy match** retrieves the complete occurrence in revision-checked chunks. **Save match…** writes an exceptionally large selection to a file. For a PDF, **Show text** includes the page’s surrounding lines. Deep zoom renders the visible part of the printed page at the requested resolution.

### Desktop-to-worker protocol

The front end launches the sibling `helloneedle-worker search` or `helloneedle-worker preview` with QProcess. It writes one UTF-8 JSON request and closes stdin. The worker streams one JSON object per stdout line. Separate the machine protocol on stdout from process diagnostics on stderr. The wire boundary avoids sharing toolkit objects, allocation ownership or an in-process ABI across Rust and C++.

A search supplies `folder`, `query`, `mode` (`document` or `source`) and the named option fields `regex`, `caseSensitive`, `hidden`, `ignored`, `filenames`, `excludeSubdirectories` (default false), and `pathPattern`. A `match` event carries file identity, relative display path, kind, revision, location, label, excerpt, and UTF-16 offsets. `start` and `length` identify the displayed excerpt. `blockStart` and `blockLength` identify the occurrence in the entire preview block. On Unix `pathBytes` and `folderBytes` can carry base64-encoded native bytes. On Windows the normal path uses Unicode.

Optional numeric `searchWorkers` and `pdfConversions` fields default to zero. The search resolves Automatic using its available logical CPU count and clamps the PDF limit to the effective worker count. Each request has its own settings, workers and resource budget. A single writer emits intact newline-delimited events. Results may arrive interleaved by file; occurrence order within a file is preserved. The Qt client uses a dedicated search pipe reader and a bounded queue of chunks. If the GUI falls behind, the worker is slowed by pipe backpressure. Only a page of documents and occurrences needs Qt tree rows. The result index remains available for late matches, cancellation and navigation.

One thread walks the folder and looks ahead four paths per available worker, with a minimum of 32 and a maximum of 1,024 queued paths. The coordinator starts readers on demand. Each reader owns one file, its decoder, and its matcher. A free worker can take a later text file while an earlier PDF waits for a conversion slot. A bounded channel carries excerpts and completion events back to the coordinator. The search runs at a lower scheduling priority than the separate, interactive preview process.

Before admitting another reader, the coordinator compares estimated working memory for the active files and the new file with half the available memory. It refreshes its memory estimate during the search. Streaming literal text reserves little memory. Regex, HTML, compressed Office documents and Poppler require larger reservations. A single large file can run on its own. These estimates control overlap and do not set a limit on the total file size. Each eligible file is scheduled once. The coordinator forwards occurrences, records per-file outcomes, and withdraws a file’s provisional content if its final revision or read fails.

The `files` field in both `progress` and `done` is the absolute number of eligible regular files examined. It advances before opening or skipping each file. The first file triggers a progress event, subsequent events are throttled during traversal, and `done` supplies the final count. The desktop resets its count for each search and can read `documentsScanned` from an older worker’s progress events. For compatible clients the worker also supplies `documentsScanned`, which counts searchable documents completed successfully, including those with zero hits. Skipped binaries, image-only PDFs and failures do not increment this secondary field.

Content matches can arrive before the end of a file. If later reads reveal binary data, fail, or detect a changed revision, a `discard` event identifies the file whose provisional content hits must be removed. Keep filename matches and results from other files. `done.count` reflects the retained matches. File errors use a separate `error` event.

A preview supplies the mode, file identity, revision, selected location and UTF-16 match position. `location.index` is zero-based in the decoded file. Human-facing line, page, paragraph and slide numbers are one-based. The `preview` response supplies context in `blocks` and its local selection in `index`. `totalBlocks` is optional. A streaming reader may stop after obtaining the selection and its context. An absent total means the full count is unknown. A clipped block supplies `textOffset` in UTF-16 units. PDF hits carry `page` and `pageLine`. A layout preview includes page-space word boxes for the selected line. `pdfPlain` identifies recovery text without word geometry. An `error` event with code `changed` identifies a stale file revision. A preview request with `copyMatch: true` streams the selected span in `matchText` frames. The GUI commits a copy or save only after complete delivery and the final revision check. The search completion event carries final counts and retains `truncated: false` for compatible clients. Canceling or replacing a request closes its process connection and prevents further updates to the view.

## Build, install, and package

### FreeBSD development builds

Each push to `development` runs the FreeBSD development workflow on FreeBSD 15.1 amd64. It builds the checked-out commit, installs its actual package and runs the worker and Qt/X11 checks against the installation. Development packages use `helloneedle-<VERSION>.a<RUN>_<ATTEMPT>-FreeBSD-15-amd64.pkg`. The same build and attempt numbers appear in the installed pkg version. The workflow uses `pkg version -t` to require a preview newer than the preceding release and older than the proposed final version. For the 1.2.0 series, the upgrade order runs from stable 1.1.0 through successive 1.2.0 previews to stable 1.2.0. This branch produces one native target. The full native matrix and release publication are separate operations. [Development workflow](.github/workflows/freebsd-package.yml) · [Native build and verification](packaging/native_ci.py)

The successful run summary links the exact tested package, SHA-256 digest, Git commit and matching source archive with vendored Rust dependencies. The run also keeps GUI screenshots and verification logs as a separate artifact. Actions downloads require a signed-in GitHub session. Compare the package’s `sha256 -q` output with the run summary, then install it with `pkg install ./<downloaded-filename>.pkg` on FreeBSD 15.x amd64. Use the selected build’s filename when upgrading. [FreeBSD development runs](https://github.com/AlfredoLlaquet/helloneedle/actions/workflows/freebsd-package.yml?query=branch%3Adevelopment) · [Installation instructions](README.md#freebsd-15-development-builds)

### Native builds and stable releases

During release preparation, verify the successful FreeBSD build job for each target. GitHub lists newer builds under the full native workflow’s job name followed by the reusable FreeBSD job name. Historical releases have a single job name. The 14.x package also requires its independent installation check on FreeBSD 14.5. [Native package verification](packaging/release/native_packages.py)

Hello Needle builds with CMake, a C++17 toolchain for Qt 6.4 or newer, Qt Widgets, Qt SVG, SQLite 3, and the separate Cargo lockfile under `bridge/`. CMake places the worker beside the GUI in the build and installed trees. Qt SVG renders the bundled button icons. System packages supply Qt, its native platform plugin and translations, Poppler utilities and antiword on FreeBSD and Linux. The FreeBSD pkg and Ubuntu Debian package install a native desktop entry. Uninstall them with `pkg delete helloneedle` or `apt remove helloneedle`. [Build instructions](README.md#build-from-source)

Windows and macOS follow the installer model used for Crumb Writer. Windows uses a per-user Inno Setup wizard. The Start menu and optional desktop shortcut open the root launcher, which looks for the private Qt and converter binaries in `bin`. A source build can still use an MSYS2 UCRT64 installation. ## Verification, including native appearance

### Project MT2 and NR verification

The installed worker suite compares serial and concurrent results, exercises simultaneous PDF limits, verifies per-file error and rollback accounting, and checks that serial and parallel searches reach the final sentinel beyond 100,000 matches. The GUI regressions exercise deep navigation, all 490 individual diagnostics, duplicate basenames, view changes and top-level-only search. The FreeBSD evidence includes the time to first match, elapsed search time and peak memory for a generated mixed-format folder. Record the actual number of processors in the test environment when interpreting comparisons. The Qt tests exercise keyboard and mouse navigation, a changing results tree, centered selections, persisted settings, and splitter spacing in both interface languages. The original files used to diagnose Windows-1252 HTML and a Word-exported text manuscript stay outside the checkout. Use newly written fixtures for CI. [Concurrency checks](tests/desktop/parallel_checks.py) · [Benchmark](tests/desktop/search_benchmark.py) · [GUI checks](tests/desktop/gui_tests.cpp)

To repeat the native benchmark, run `python3 tests/desktop/search_benchmark.py --worker /usr/local/bin/helloneedle-worker`. It generates six files each of PDF, DOCX, text and JSON, tests settings 1, 2, 4 and Automatic, and repeats each search immediately. Processor availability can limit a requested setting. The operating system controls the disk cache. Sampled peak RSS includes the worker and its converters and can count shared pages more than once. The benchmark checks that the system reports resident memory for its own process group before timing searches and requires a positive sample for every measured run.

The FreeBSD 15.1 amd64 development build at `344c1dbb2330ce67f7c28bb3fa9c165fdb281964` verified 100,001 matches with both serial and parallel searches and retained all 490 file errors. The installed development package passed all 12 native X11 scenarios. [Development build and test evidence](https://github.com/AlfredoLlaquet/helloneedle/actions/runs/45715916314)

### Shared verification procedures

The large-HTML and status-bar checks exercise the same worker and Qt controls as the desktop. The native Linux GUI tests intercept the browser URL and check activation at the beginning, middle and end of the link as well as from the keyboard.

On a clean Windows installation, the Start menu test records exit codes for both the installed GUI and its launcher. The directory-picker fixture resolves the temporary profile path first because Windows can give the same folder a short name such as `RUNNER~1` and a full name. The installer tests also repair the installation in Spanish, remove it, and verify the original documents by checksum. [Windows installer tests](tests/installer/verify-windows.ps1)

For older Word documents, the worker requests UTF-8 text from antiword. The macOS package includes the character maps supplied by MacPorts. The `UTF-8.txt` map selects the bundled data directory. Antiword uses its separate `fontnames` table for formatted output. The clean-install test reads a Word for DOS document containing `café` so a missing or incorrect text mapping is visible. [Document conversion](bridge/src/converters.rs) · [Installed-document tests](tests/installer/runtime-check.py)

The native Word piece-table reader uses the MIT-licensed `cfb` crate for compound storage. The worker handles compressed and UTF-16 pieces and separates field results from field instructions. The short multilingual DOC and the corresponding text source are under `tests/desktop/fixtures/`. A second Word fixture contains a recorded deletion and manually hidden text.

The filename test passes the exact bytes returned by a search into the preview request. On a filesystem that accepts non-UTF-8 names, it uses a name containing the byte 0xFF. On APFS, which rejects that fixture, it uses a decomposed accented filename and verifies its exact bytes.

The fast worker check exercises the same process protocol used by the desktop. The fixture generator writes a three-page PDF with repeated words on page two, rich Word and ODF paragraphs split across formatting, an XLSX and ODS value at Quarterly!C7, a slide-two match, RTF, markup, and original plain text with an emoji before two hits. `fixtures/sample.doc` is a real binary Word file generated from the tracked original `sample.txt` with LibreOffice Writer's “MS Word 97” export filter. Hash comparisons confirm that search and preview leave the originals byte-identical.
